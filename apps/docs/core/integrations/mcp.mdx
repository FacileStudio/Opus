title: MCP
description: Connect Opus to MCP clients like Cursor and Claude Desktop using the official Opus MCP server.

Opus supports the Model Context Protocol (MCP) in two ways:

1. **Built-in HTTP endpoint** — every Opus instance exposes `/api/mcp` out of the box. No extra setup, no extra process.
2. **Stdio package** (`@opus/mcp`) — a local stdio server for clients that prefer stdio transport.

Both offer the same tools for managing workspaces, projects, tasks, comments, and labels.

## Built-in HTTP endpoint

Every Opus API instance ships with a Streamable HTTP MCP endpoint. This is the recommended approach for self-hosted deployments.

Point your MCP client at:

```
https://your-opus-instance.com/api/mcp
```

On first connect, you will be redirected to Opus's login page. After you sign in, all MCP tools run as your authenticated user.

The endpoint implements OAuth 2.1 with PKCE for authentication. Discovery metadata is available at:

- `/.well-known/oauth-protected-resource/api/mcp`
- `/.well-known/oauth-authorization-server/api`

## Stdio package

The `@opus/mcp` package runs a local stdio MCP server and authenticates with Opus using device authorization. Use this when your MCP client requires stdio transport.

### Prerequisites

- Node.js 20 or newer
- A running Opus API
- Access to the Opus web app to approve device login

By default, self-hosted Opus allows both `opus-cli` and `opus-mcp` as device auth client IDs.

### Install and register

Use the recommended interactive installer:

```bash
npx @opus/mcp
```

The installer lets you choose where to register the server configuration:

- Cursor (user-wide)
- Cursor (project-level)
- Claude Desktop
- Custom JSON config path

You can also run the explicit install command:

```bash
opus-mcp install --target cursor-user -y
```

Use `--help` to see all available targets and flags:

```bash
opus-mcp install --help
```

### Point to a self-hosted instance

When generating config, pass your Opus base URL:

```bash
opus-mcp install --target cursor-user -y --api-url https://opus.example.com
```

Or set it via environment variable:

| Variable | Description |
| --- | --- |
| `OPUS_API_URL` | Opus API origin. Default: `http://localhost:1337`. Do not include `/api`. |
| `OPUS_MCP_CLIENT_ID` | Device auth client ID. Default: `opus-mcp`. |

If you override `OPUS_MCP_CLIENT_ID`, make sure it is included in [`DEVICE_AUTH_CLIENT_IDS`](/core/installation/environment-variables).

### Authentication flow

On the first tool call that needs Opus access, the MCP server:

1. Requests a device code from Opus
2. Prints a verification URL and user code
3. Opens the browser when possible
4. Polls until you approve sign-in
5. Stores credentials in `~/.config/opus-mcp/credentials.json`

## Available tools

Both the HTTP endpoint and stdio package expose the same tools:

- Session: `whoami`, `list_workspaces`
- Projects: `list_projects`, `get_project`, `create_project`, `update_project`
- Tasks: `list_tasks`, `get_task`, `create_task`, `update_task`, `move_task`, `update_task_status`
- Comments: `list_task_comments`, `create_task_comment`
- Labels: `list_workspace_labels`, `create_label`, `attach_label_to_task`, `detach_label_from_task`

## Debugging

To run the stdio server directly:

```bash
npx @opus/mcp serve
```

When running from source in this monorepo:

```bash
pnpm --filter @opus/mcp run build
pnpm --filter @opus/mcp run start
```
