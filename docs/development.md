# Opus — Development

Local setup, the commands you will actually use, how migrations work, and the quality gate that
runs before every commit.

## Prerequisites

| Tool | Version | Why |
|---|---|---|
| Node | 20.19 or later | Enforced by `engines` in the root `package.json` |
| pnpm | 10.32.1 | Pinned as `packageManager`. Not npm, not yarn, not bun |
| PostgreSQL | 16 | Matches the image the compose file uses |
| Docker | any recent | Only needed for the Postgres container or a full-stack run |

The container runs the built API under Bun, but development runs it under Node with `tsx`.

## Setup

```sh
pnpm install
cp .env.sample .env
```

Fill in `POSTGRES_PASSWORD` and `AUTH_SECRET` at minimum:

```sh
openssl rand -hex 32
```

If you only want Postgres from Docker:

```sh
docker compose up -d postgres
```

## Run

```sh
pnpm dev
```

Turborepo starts every workspace with a `dev` task: the API on `:1337` and the web client on
`:5173`. To run one at a time:

```sh
pnpm --filter @opus/api dev
pnpm --filter @opus/web dev
```

The API prints its resolved public URL on boot. The interactive OpenAPI reference is at
`http://localhost:1337/docs`, and the raw spec at `/docs/openapi.json`.

## Database migrations

Migrations are SQL files in `apps/api/drizzle/`, generated from `apps/api/src/database/schema.ts`.

```sh
pnpm --filter @opus/api db:generate   # after changing schema.ts
pnpm --filter @opus/api db:migrate    # apply manually
pnpm --filter @opus/api db:studio     # Drizzle Studio
```

`runStartupTasks` applies pending migrations on every API boot, so in development you usually only
need `db:generate`. Around the Drizzle migrator sit several hand-written reconciliation steps
(workspace user email backfill, session column, API key `reference_id`, notification preference
schema, GitHub integration, columns). Order matters — read `apps/api/src/index.ts` before adding
one.

Seed a workspace with sample data:

```sh
pnpm --filter @opus/api db:seed:user-data
```

## Tests

```sh
pnpm test              # Vitest unit tests across every workspace, via Turbo
pnpm test:integration  # API integration tests — needs a running PostgreSQL
```

Unit tests live in `tests/api/` (events, plugins, redis, storage, utils, ws) and alongside the web
client. Integration tests live in `tests/api-integration/` and cover config, device authorization,
health, labels, the OpenAPI spec, projects and tasks. Setup and fixtures are in
`tests/api-integration/setup.ts` and `helpers/`.

Watch mode and coverage:

```sh
pnpm --filter @opus/api test:watch
pnpm --filter @opus/api test:coverage
pnpm --filter @opus/web typecheck
```

## Quality gate

The gate is lefthook (`lefthook.yml`), pulling the shared commit-msg policy from
`FacileStudio/hooks` at `ref: v1` and adding local pre-commit jobs on top:

- `pre-commit` runs `pnpm exec biome ci .` then `pnpm run build`. The full build on every commit
  is deliberate and slow — make sure the code compiles before you commit.
- `commit-msg` (shared `common.yml`) validates Conventional Commits and prepends the gitmoji —
  never write the emoji yourself; the hook derives it from the type.
- Hooks install via `mise install` (`[hooks] postinstall = "lefthook install"` in `mise.toml`).
- The `build` pre-commit job needs the mise toolchain on PATH (node ≥ 20.19 for Vite 7);
  a bare shell without it fails with `crypto.hash is not a function`, which is the
  environment, not the code.

Formatting and linting are Biome (`biome.json`): spaces for JS and TS, tabs elsewhere, double
quotes, semicolons required, imports auto-sorted. CSS and `package.json` are excluded.

```sh
pnpm lint   # biome check --write across the monorepo
```

## Internationalization

Translations are JSON files in `i18n/`, currently `de-DE`, `el-GR`, `en-US`, `es-ES`, `fr-FR`,
`mk-MK`, `nl-NL` and `ru-RU`, validated against `i18n/schema.json`.

```sh
pnpm i18n:check       # validate
pnpm i18n:check:fix   # auto-fix
pnpm i18n:report      # coverage report per locale
pnpm i18n:schema      # regenerate the schema
```

## Conventions

- Routes live in `apps/api/src/<feature>/index.ts`; business logic in
  `apps/api/src/<feature>/controllers/`.
- Every route is declared with `describeRoute` for OpenAPI and `validator` with a Valibot schema.
  A route without both will not show up correctly in `/api/openapi`.
- All tables use CUID2 primary keys, `createdAt` / `updatedAt` timestamps, and explicit cascade
  rules on foreign keys.
- Read auth context with `c.get("userId")`, `c.get("user")`, `c.get("session")`.
- Call `publishEvent` from `apps/api/src/events/` to record activity and fan out over WebSockets.
- Throw `HTTPException` for errors.
- On the client: fetchers in `src/fetchers/<feature>/`, query hooks in `src/hooks/queries/`,
  mutation hooks in `src/hooks/mutations/`. TanStack Query owns server state, Zustand owns client
  state.
- `apps/web/src/routeTree.gen.ts` is generated by the TanStack Router plugin. Do not edit it.
- No inline comments in code.
